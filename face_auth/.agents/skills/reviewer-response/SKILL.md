# Reviewer Response

Treat each reviewer comment as a traceable requirement.

## Workflow

1. Preserve the reviewer's original meaning.
2. Classify the issue: clarification, writing, methodology, experiment, baseline, ablation, analysis, literature, limitation, or presentation.
3. Identify what evidence currently exists.
4. Identify the smallest action that directly addresses the comment.
5. If an experiment is required, use `experiment-planner` before implementation.
6. Track code, config, run, result, table/figure, and manuscript location.
7. Draft the response only from completed changes and available evidence.
8. Mark partially addressed or unresolved points explicitly.

## Response Record

Maintain:
- reviewer comment;
- issue identified;
- action taken;
- evidence/result;
- manuscript change and location;
- concise response text.

## Guardrails

- Never claim work was completed when it was not.
- Never invent reviewer intent.
- Never overstate results.
